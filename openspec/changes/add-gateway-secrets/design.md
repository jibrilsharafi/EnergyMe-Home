## Goals / Non-Goals

**Goals:**
- No credential in plain text in any cloud record (command params, `command_events`, shadows, shadow history, logs).
- A captured envelope cannot be retargeted or moved to another device.
- A secret can only reach the one LAN endpoint it was bound to: its ip:port, and for an on-link target the MAC the request carries, checked against ARP before the first byte of every request that expands it (add-gateway-modules `Target MAC binding`). Residual, accepted: a routed (off-link) target matches by ip:port only.

**Non-Goals:**
- Protection against an operator who holds gateway command rights. Such an operator can already drive the bound equipment through `${secret:...}`, can replay a captured envelope (D4) and could try reflection tricks on the target; the echo scrub is best effort. Rights are an IAM question (lan-tunnel 5.1 / 5.2 follow-ups).
- Encryption at rest, flash encryption, eFuses (manufacturing ADR-6).
- Physical attackers (flash dump yields `key_pem` and the slots alike).
- The HTTPS module itself (add-gateway-modules). Secrets expand into `https` only on a product where that module's bench gate has passed; until then the executor's module availability check returns `MODULE_UNAVAILABLE` before expansion, and plain `http` is the fallback. With plain HTTP the expanded secret crosses the LAN in clear, as it does when a person uses that equipment's web UI.
- Web UI.

## Decisions

### D1. One blob per slot, fixed keys `s00`-`s15`
NVS key names are limited to 15 characters and secret names to 24, so the name lives inside the blob and lookup scans the 16-entry RAM cache. One `setBlob` per rotation is atomic in ESP-IDF NVS (new entry written, old erased), so a power loss leaves either the old or the new value. Bytes 32-37 of the header are reserved and zero; an earlier draft kept a slot MAC there, and a slot written in that layout fails decoding and is erased at boot (dev only, prod held no secrets). 16 slots × at most 304 B ≈ 11 NVS entries each, about 5.6 KB worst case of the shared 64 KB partition. Alternatives: one key per field (non-atomic rotation, more entries), one blob for the whole store (every rotation rewrites 4.9 KB, larger wear and failure window).

### D2. Namespace in the excluded list plus explicit factory-reset clear
Adding `secrets_ns` to `EXCLUDED_NVS_NAMESPACES_LIST` removes it from backup and restore in one place but also from `clearAllPreferences()`, so `_factoryReset()` clears it explicitly next to `auth_ns`. It is also added to `TO_INITIALIZE_NVS_NAMESPACES_LIST`. `Secrets::begin()` runs after `createAllNamespaces()` and before the gateway and MQTT start.

### D3. Envelope v1 and an authenticated `issued_at`
RSA-OAEP-SHA256 key wrap plus AES-256-GCM, as decided in the brief. The brief's AAD `energyme-secret-v1|<device_id>|<name>|<ip:port>` is extended with `|<mac>|<issued_at>`. The MAC field is always empty, since the target MAC travels on each gateway request (D6a); it stays so envelope v1 and its golden vectors do not change. `issued_at` becomes the slot's `set_at`. `kid` (AWS certificate id = SHA-256 of the cert DER) lets the device reject an envelope for another key before a costly RSA operation and lets the tool pick the right certificate when a thing has several principals; the device computes it once at `Secrets::begin()` from `cert_pem`. All crypto failures map to one code so the device is not a padding or tag oracle. Never PKCS#1 v1.5 (Bleichenbacher). The plaintext is `len` u16 + value + zero padding to 258 bytes, so the archived `ct` (always 258 bytes) does not reveal the value length; the device checks `len` and the padding after authentication. Values must be strict UTF-8 without NUL, CR, LF, which keeps raw expansion from injecting header lines and gives `|json` a defined result.

Device implementation notes, all covered by tasks: read `key_pem` into its own zeroized PSRAM buffer per operation, never borrow `_awsIotCorePrivateKey` (other task, no mutex, wiped on reconnect); `mbedtls_pk_parse_key` length is `strlen + 1` for PEM; pass a CTR-DRBG as `f_rng` (blinding is mandatory in mbedTLS 3.x); call `mbedtls_rsa_set_padding(rsa, MBEDTLS_RSA_PKCS_V21, MBEDTLS_MD_SHA256)` before decrypt, else it silently uses v1.5; require the unwrapped length to be exactly 32; `mbedtls_gcm_auth_decrypt` with a 16-byte tag; `mbedtls_platform_zeroize` on key, plaintext and PEM buffers; `mbedtls_pk_free` on every path.

### D4. No replay protection: the last set wins
Replaying a captured envelope means dispatching a gateway command to the device, which only someone with command rights can do, and those operators are a Non-Goal. The AAD already pins device, name and ip:port, so the worst a replay can do is roll a credential back to an older value or bring back a deleted one, after which the next poll fails closed and the operator sets it again. Accidental late redelivery is bounded by the existing 300 s `created_at` guard. So `secret_set` needs no clock: the decrypted value is stored with `set_at = issued_at`, whatever the slot held; a delete erases the slot; a local REST set stamps `set_at` from the device clock, or 0 when it is not synchronised. One clock-free check stays because it is trivial and makes AWS redelivery cheap: a slot with the same name, `set_at` and target is an already applied envelope and returns `applied: "false"` without decrypting. If last-writer-wins between concurrent operators is ever wanted, a per-slot "issued_at not older than set_at" check can be added; delete still erases, so delete then set always recovers. Rejected: a namespace high-water mark with a freshness window (made secret writes depend on the device clock, needed a ceiling against a wrong-future NTP answer and a wait-and-retry loop in the tool).

### D5. Ops run in the gateway task, under the existing switches
The RSA private operation (expected tens to a few hundred ms) must not run on the MQTT task, so both ops go through `Gateway::submit()` as new `GatewayLogic::Op` values, dispatched by the add-gateway-modules command adapter (they open no socket, so they are not executor modules), and use the existing slot (with whatever busy rule `lan-gateway` specifies at the time, `GATEWAY_BUSY` today, possibly a bounded wait after add-lan-collector) and kill switch (`GATEWAY_DISABLED`). The `lan-gateway` envelope requirement is not modified in this change because three other changes touch it; the op list is extended by an ADDED requirement in `gateway-secrets`, and the `UNKNOWN_OP` description string in `mqtt.cpp` grows. This change requires add-gateway-modules, so the ops are written against its adapter, not today's `_run()` switch. Local REST management works with the gateway disabled (local admin; values are inert while the gateway is off).

### D6. A `secret` resolver in the one engine, gated on module and target
There is one tokenizer, the add-gateway-modules engine, so the binding check always runs on the same parse as the expansion. `secrets_logic` holds no grammar; it provides the resolver decision (`decide(module, ip, port, arg, cache)` returning a slot or a reason code) and the scrub, both pure and host-tested. The resolver is never registered globally. The engine takes a per-call `Resolver*` chain (add-gateway-modules D7): the command adapter passes the `secret` resolver alone and the collector appends it after its own `now`, `cursor`, `var` and `cap` resolvers, so collector names stay `BAD_TEMPLATE` in one-shot commands. The executor passes module, target IPv4 and effective port in the resolver context (MODIFIED `gateway-modules` requirement, which also lets the resolver return its own reasonCode instead of `BAD_TEMPLATE`). The resolver answers only for `http` and `https`, one-shot or collector step; for `tcp` it fails with `SECRET_MODULE_NOT_ALLOWED`, because a raw TCP reply has no defined structure to scrub and a `tcp` grant covers the whole target. `udp`, `modbus_tcp` and tunnel bytes are never templated by the engine, so a secret cannot reach them. On success it reads the value from NVS into a PSRAM scratch, hands it to the engine (which applies the up to 3 encodings into its zeroized output buffer), records the token's name and final encoded form for the scrub, and zeroizes the scratch. The engine grammar is followed as is: `$${` escape, chained encodings, `BAD_TEMPLATE` for malformed placeholders, untemplated fields (`body_b64`, header names) sent literally, which is safe since nothing is resolved there. A cap of 8 `secret` placeholders per request bounds NVS reads. Rejected: a secrets-specific tokenizer (two parsers can disagree, and its field list and `BAD_ARGS` rule contradicted the engine), allowing `tcp` (unscrubbable reply).

### D6a. The target MAC travels on the request, not the slot
An ip:port binding fails open on DHCP LANs: once the meter or XWEB is renumbered, whatever host takes its address receives the credential on the next poll. add-gateway-modules carries the target `mac` on the request (the one-shot `mac` argument, or the collector job `target`) and requires it on an on-link request that expands a sensitive placeholder, whatever the access class, so a polled GET with `Authorization: Basic ${secret:meter_basic|b64}` is covered too. Without it the request is `SECRET_TARGET_MISMATCH` with `MAC_REQUIRED` after expansion and before any socket; with it the executor does its one ARP compare after connect and before the first byte (before the ClientHello for `https`), and a request carrying `mac` to an off-link target is `TARGET_MAC_CHANGED`. The store therefore keeps no MAC: one MAC per request, never a second copy per secret that the operator must type again and that can disagree with the first. On-link status is decided at run time, never at set time. Rejected: a MAC on the slot and inside the AAD (a second copy with its own compare path; inside the AAD it only stopped an operator with command rights from retargeting a secret, a Non-Goal).

### D7. Echo scrub, best effort
LAN equipment often echoes form fields in error pages, and results land in `command_events` forever. For each expanded token the raw value and the final encoded form of its chain (each if at least 4 bytes) are replaced in status line, headers and body with the fixed 4-byte marker `****`; for `https` this runs on the decrypted reply. Intermediate forms of a chain (the `|url` text inside `|url|b64`) are not scrubbed, since they never went on the wire. Values shorter than 4 bytes are not scrubbed (too many false hits). Transformed reflections (HTML-escaped, case-changed) are not caught; see Non-Goals.

The marker is never longer than the shortest scrubbed form, so the scrub runs in place, longest match first in one forward scan, with the write index never past the read index: the output never grows, no buffer cap, cut or scratch is involved, and the marker reveals nothing about the value length, which keeps the 258-byte envelope padding meaningful. When a reply was cut on receive, a trailing prefix (at least 4 bytes) of any form is dropped, so a partial value never ends the published body. Nothing consumes which secret was echoed; `redacted` signals that a replacement happened.

One layer owns the secret scrub, the executor. The result scrub of the `secret` resolver is registered with the executor, the only registration this change makes, and the executor runs it before `run` returns, so the command adapter and collector steps get the same scrubbed `ExecResult` plus a boolean `redacted`. The adapter publishes it as `redacted: "true"`. The collector never scrubs secrets a second time; it OR-s `redacted` into its part header `rd`. A second secret pass would find nothing left, so `rd` would lose the replacement signal, which is why the flag travels in the result.

### D8. Metadata in the `system` shadow
Reported-only object `secrets` in `system`. Reasons: drift detection already rebuilds `system` every 3 s (`shadow.cpp:409-416`), so local REST changes reach the cloud with no new plumbing; the gateway switches already live there (`shadow.cpp:655-658`); `system` is already in infra `KNOWN_SHADOWS`, so no infra change; shadow history in Iceberg gives a rotation audit trail with metadata only. A delta on `secrets` goes through the existing unknown-field path (nulled, WARNING). Rejected: `info` (reported-only but not drift-checked, a local change waits for the next reconnect), `collector` (belongs to add-lan-collector, wrong layer, its own 2 KB reported budget), command results only (no standing view for the tool to read `kid`).

Size of the whole `system` document. The AWS limit is 8192 bytes of state per named shadow. This design assumes `desired` and `reported` count together, the conservative reading add-lan-collector also adopts (its open question), so a looser reading needs no change. Worst case, compact JSON:

- `desired` while the cloud writes a full grant list: `gateway_write_grants` at its 3072 B cap (add-gateway-modules) plus keys, about 3.1 KB.
- `reported` `gateway_write_grants`: the old list, also up to 3072 B plus key, about 3.1 KB.
- `reported` fields of `_reportSystem()` (`shadow.cpp:645-658`: brightness, two send flags, two publish limits, three log levels, two switches) about 0.28 KB, `tunnel_ports` with 16 five-digit ports about 0.11 KB, `tunnel_active` with a session about 0.12 KB. About 0.51 KB together.
- `reported` `secrets`: header with the 64-hex `kid` about 0.09 KB, plus 16 slots as `[name, "ip:port", set_at]` with 24-character names, 15-character IPs and 5-digit ports at 63 B each, about 1.01 KB. At most 1.1 KB.

Total about 7.8 KB, under 8192 B by roughly 0.4 KB. A keyed slot object (`{name, ip, port, set_at}`, about 92 B) would make `secrets` about 1.6 KB and the total about 8.3 KB, so AWS would refuse the cloud grant write or the device's reported update. Hence the positional slot form, with `max` dropped (constant 16, still returned by REST). `kid` stays in full because the tool selects the certificate by it. The margin is small, so e2e task 7.6 measures the real document with read-only `GetThingShadow` on dev with a maximal grant list reported and pending in desired, 16 maximal secrets, 16 `tunnel_ports` and an active tunnel. If it exceeds 8192 B, this design is revised before merge (next lever: report a 16-hex `kid` prefix and let the tool match by prefix). Task 7.6 extends add-gateway-modules task 5.3, which measures grants without slots.

### D9. Dev NVS browser: namespace-level opacity
Key-name matching would not catch `s00`. The browser redacts every entry of `secrets_ns` and refuses raw writes there, since a raw blob write would bypass name, target and value validation and desync the RAM cache.

### D10. Operator tool
`source/utils/gateway_secret.py`, sibling of `shadow_cli.py`, boto3 already a dependency, `cryptography` added with `uv add`. Read-only calls for discovery (`iot:ListThingPrincipals`, `iot:DescribeCertificate`, `iot-data:GetThingShadow` for `kid`); no MAC (it travels on each request); `issued_at` is the tool's current time and each `set` sends one envelope, without retry; `iot-jobs-data:StartCommandExecution` with the existing `energyme-<product>-<env>-gateway` template to dispatch, prod guarded by an explicit confirmation like the lan_tunnel tool. A golden vector (test-only RSA key pair committed under `source/utils/tests/fixtures/`, clearly named test-only, never a device key) is shared between pytest and the bench decrypt check.

## Risks / Trade-offs

- [`command_events` keeps every envelope forever; a later leak of a device key decrypts its history] → Envelopes for a device are only useful with that device's key, which leaks only with physical access, which also yields the plaintext slots. Rotate the LAN credential after a device is lost.
- [A captured envelope can be replayed by someone with command rights, rolling a credential back or restoring a deleted one] → Non-Goal (D4); the AAD keeps it on its device, name and ip:port, a stale credential fails closed at the next poll, and the operator sets it again.
- [Local REST `PUT` sends the value over plain HTTP on the LAN] → Same exposure as using the equipment's own HTTP UI on that LAN; digest auth keeps out unauthenticated writers. AsyncWebServer body buffers cannot be zeroized; they are freed right after the request.
- [RSA OAEP-SHA256 or the stack budget fails on the device] → Task 1 measures before any store code. Fallback A: if `PKCS1_V21` with SHA-256 cannot be made to work, envelope `alg` `RSA-OAEP+A256GCM` (OAEP with SHA-1, still IND-CCA2) with the same AAD and `v: 1`, recorded here. Fallback B: if gateway stack high-water during decrypt leaves under 1.5 KB free, raise `GATEWAY_TASK_STACK_SIZE` (internal RAM, measured cost) rather than moving the op to another task.
- [A legitimate NIC or controller replacement changes the MAC] → requests carrying the old MAC stop with `TARGET_MAC_CHANGED` until the caller sends the new one; the secret itself needs no change. Failing closed is the intent, as for grants.
- [Full `system` shadow close to 8 KB] → positional slot form (D8) and the measured worst case in task 7.6.
- [Short or common values cause scrub false positives] → 4-byte floor; scrub only on results of requests that expanded a secret.
- [Crash during expansion leaves the value in a core dump] → Zeroize narrows the window; core dumps stay on the device unless explicitly fetched.
- [NVS partition full] → `NVS_WRITE_FAILED` distinct from `SECRET_STORE_FULL`; init logs free entries at DEBUG.
- [Refusals on an expanded value act as an oracle on it (adversarial review)] → write-grant matching and the request line see the expanded path, so a `secret` placeholder in a path is refused with `BAD_TEMPLATE`; credentials go in header values or the body. The one-send size check still sees the expanded length, a residual that needs many commands per bit and is left to command rights (Non-Goals).
- [The store lock was held across the RSA operation] → the repeat, kid and slot checks run under the lock, the decrypt runs outside it, and the kid and free slot are checked again under the lock before the write, so the shadow report and REST never wait on RSA; a lock timeout leaves the `secrets` key out of the report (503 on REST) instead of reporting an empty store.
- [A PSRAM failure while recording an expanded token would leave an echo unscrubbed] → the engine's `expanded` hook can refuse, and the request fails with `NO_MEMORY` before any byte is sent.

## Migration Plan

New namespace, no data migration. Firmware without this change rejects the ops with `UNKNOWN_OP`, so the tool needs no version check. After rollout, rotate the XWEB password on the XWEB, store it with `gateway_secret.py set`, and switch the XWEB commands to `${secret:xweb_admin|url}` with the XWEB MAC (from `net_scan`) on each request or job target. Dev slots written by a build that kept a slot MAC fail decoding and are erased at boot; set them again once (prod holds no secrets). Rollback to older firmware leaves `secrets_ns` in NVS unused. Older firmware does not list it as excluded, so its factory reset clears it, but its configuration backup would export the slots as blobs: delete all secrets (`gateway_secret.py delete`) before a `firmware_rollback` to a pre-secrets build.
